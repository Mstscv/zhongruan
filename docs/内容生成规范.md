# 内容生成规范 v1

> 适用范围：`content/bank`（客观题）、`content/handbook`（手册）、`content/cases`（案例）。
> 一切规则的机器可执行版本见 `src/types/schema.ts` 与 `tools/validate-content.ts`；两者冲突时以代码为准。
> 每一批内容写完必须跑 `npm run validate`，**报错不许绕过**，改到通过为止。

## 0. 总原则

- **零基础友好**：假设读者从未学过项目管理。首次出现的术语要用一句大白话解释。
- **以官方为准**：知识点表述对照《系统集成项目管理工程师教程（第3版）》（清华大学出版社，2024）；拿不准的宁可不写，不编造。
- **应试导向**：每道题、每节手册都应对应大纲里一个明确考点（`topic` 编号），不考的不写。
- **措辞严谨**：不使用"一定/绝对/唯一"等容易被命题反例推翻的表述，除非教材确实如此。

## 1. 客观题（单选，`content/bank/chXX/shard-NN.json`）

文件是**一个 JSON 数组**，元素结构见 schema。要点：

| 字段 | 规则 |
|---|---|
| `id` | `Q-C07-0001` 格式：`Q-C` + 两位章号 + 四位序号；**序号全章连续**，shard-01 用 0001–0040 段，shard-02 从下一个空号续；全章、全库唯一 |
| `chapter` | 必须与所在目录一致（如 `ch07`） |
| `topic` | 必须是 `content/meta/chapters.json` 里该章已有的知识点编号（如 `"7.3"`） |
| `difficulty` | 1=识记 2=理解 3=应用/计算；**每片约 3:5:2**，难度3 占比 ≥10% |
| `stem` | 10–80 字；问法自然（"以下关于X的说法，正确的是…"、"…是多少？"）；**禁止**出现"正确答案""本题答案"；不出现能直接定位章节的泄题线索（除非考点本身就是章名） |
| `options` | **恰好 4 条、互不相同**；长度相近（最长 ≤ 3×最短，尽量 ±15 字内）；编号类选项（A. B. C. D. 前缀）不放进 option 文本，UI 会加；"以上都对/都不对"全片 ≤1 题 |
| `answer` | A–D；**全片分布均衡**，每个字母占 20%–30%；禁止出现规律性模式（如连续 3 个 B） |
| `explanation` | **60–150 字**（硬底线 40）。结构：① 为什么对（引用教材逻辑/公式验算）；② 至少点出 1 个强干扰项错在哪；③ 计算题必须写出代入过程 |
| `tags` | 2–4 个考点关键词（用于日后再做标签筛选） |
| `source` | 固定 `"AI 原创模拟"` |

**计算题额外要求**：数字必须可验算，答案选项围绕正确值设置合理陷阱（如把总时差写成自由时差）；解析里给出公式与代入。

**质量自查（写完一 shard 后逐条过）**：
1. 随机遮住答案，自己做一遍——每题只有一个无可争议的答案；
2. 每个干扰项都能说出"错在哪"；
3. 连读 5 题题干，语气是否有变化（不要全是"下列…正确的是"）；
4. `npm run validate` 通过。

## 2. 手册（`content/handbook/chXX/NN-N-标题.md`）

- 文件名：`章号(两位)-节号-标题.md`，节号对应 topic（`07-3-排列活动顺序.md` → topic 7.3；一节一个文件）。
- 首行必须是一级标题：`# 排列活动顺序`。
- 结构模板（800–1500 字）：

```markdown
# 排列活动顺序

> 零基础导读：这一节解决什么问题？用 1–2 句大白话讲清楚。

## 1. 概念与要点
（正文，分层，关键术语**加粗**并随文解释）

## 2. 关键考点
> 💡 **关键考点**：…
（引用块，写 1–3 条本节最爱考的点，可含公式）

## 3. 常见考法
（本节在选择题里通常怎么问、容易掉的坑）

## 4. 速记
（口诀/对比表，能编就编，编不出就省略本小节）
```

- 涉及公式/表格用 Markdown 表格；重要规则用 `> 💡` 引用块。
- 结尾必须有一行：`*本节内容为 AI 整理，以官方教程（第3版）对应章节为准。*`

## 3. 案例（`content/cases/chXX/CASE-00X01.json`）

- `id`：`CASE-` + 五位数字，第 7 章用 00701 起，全库唯一；`chapter` 与目录一致。
- `scenario`：200–400 字背景，像真实项目情境（谁、什么项目、出了什么事），**含可提取的计算数据**（若为计算类案例）。
- `questions`：2–4 问；每问有：
  - `prompt`：明确的作答指令（"请计算…并说明…"）；
  - `score` 与 `scoringPoints`：**逐条得分点，分值合计 = 该问 score**（如"写出公式(1分)、代入正确(2分)、结论(1分)"）；
  - `answer`：参考答案正文（含计算过程）；
  - `keywords`：≥2 个关键词（UI 高亮用）。
- `score`：总分 = 各问之和。
- `referenceAnswer`：逐问整合版，可直接打印。
- `level1Hint`：卡壳时回看的手册节（如 `"回看手册 7.5 制定进度计划"`）。

## 4. 批次协议

1. 一批 = 一个 shard / 一章手册 / 一章案例；
2. 写完 → `npm run validate` 通过 → `npm run gen` 刷新清单 → git commit（`content: ch07 shard-01 +35题`）→ 在 `content/CHANGELOG.md` 记一行；
3. 上一批未过校验，不开下一批。
