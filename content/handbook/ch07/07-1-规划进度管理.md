# 规划进度管理

> 零基础导读：做进度之前先定"游戏规则"：用什么单位记时间、允许多大误差、偏差到什么程度要上报、多久汇报一次。本节讲的就是这份规则文件——**进度管理计划**，它不写具体哪天干什么，只写进度该怎么管。

## 1. 概念与要点

**规划进度管理**属于规划过程组，任务是编制**进度管理计划**，为后续"定义活动、排列顺序、估算时间、制定计划、控制进度"立规矩。它一般在规划阶段早期就启动，可与范围、成本规划并行，并随项目推进**渐进明细**，不是出事后的补救动作。

**进度管理计划**是程序性文件，回答"进度怎么管"，常见条款有：

| 条款 | 大白话含义 |
|---|---|
| 项目进度模型 | 用什么工具、什么方法（如关键路径法）建模 |
| 计量单位 | 工期用日历天、工作日还是人天来记 |
| 准确度 | 估算允许的误差区间，如 ±5% 或 ±2 天 |
| 控制临界值 | 偏差超过多少才需要采取措施或上报 |
| 绩效测量规则 | 进度绩效怎么算、按什么口径报 |
| 报告格式与频率 | 谁、多久、用什么模板看进度 |

它还可能约定**进度计划的发布与迭代频率**（如每周滚动更新）、**进度模型的维护规则**（谁有权改网络图）、**变更审批流程**等。

注意三条边界：一是**进度管理计划 ≠ 进度基准**，基准是经批准的进度模型，用来比对实际；二是计划里不写活动清单和具体日期，那是后面各过程的产出；三是该计划贯穿项目始终，不只是收尾时的对比材料。

**输入**方面，规划进度管理会用到项目章程、项目管理计划中的其他子计划（如范围基准、范围管理计划）、事业环境因素（如组织文化、项目管理信息系统）与组织过程资产（如历史信息、模板、进度计划软件）。**工具**上常用专家判断、数据分析和会议。

## 2. 关键考点

> 💡 **关键考点**：
> 1. 产出辨析：本过程产出**进度管理计划**；活动清单属于定义活动，进度基准属于制定进度计划，甘特图只是展示形式。
> 2. 计划内容清单：计量单位、准确度、控制临界值、绩效测量规则、报告格式与频率、进度模型维护——"规则"而非"日程"。
> 3. 准确度与控制临界值的区分：准确度管估算误差区间，控制临界值管偏差大到什么程度必须行动。

## 3. 常见考法

- 问规划进度管理的直接产出，干扰项常给"进度基准""活动清单""甘特图"。
- 问哪些内容属于进度管理计划，把"活动依赖关系、资源数量、具体起止日期"混进来当干扰。
- 问"准确度""控制临界值"各自规定什么，两者互相冒充。
- 给一个项目情境，问规划阶段何时开展、是否随推进细化。
- 问组织过程资产对进度规划的帮助（模板、历史数据、进度工具）。

常见坑：把进度管理计划当成进度计划本身；认为计划一经批准永不修订；把活动级细节写进管理计划的条款里。

## 4. 速记

口诀：**"模型单位准不准，临界绩效报给谁"**——进度模型、计量单位、准确度、控制临界值、绩效测量、报告格式与频率。

| 文件 | 回答的问题 | 什么时候有 |

| 进度管理计划 | 进度该怎么管 | 规划进度管理 |
| 活动清单 | 要做哪些事 | 定义活动 |

| 项目进度计划 | 按时间展示的安排 | 制定进度计划 |
