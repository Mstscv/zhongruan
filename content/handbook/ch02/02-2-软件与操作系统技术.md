# 软件与操作系统技术

> 零基础导读：软件从提出想法到最终退役要经过哪些阶段？操作系统到底替我们管什么？本节把生命周期、中间件、五大管理、进程与死锁、嵌入式特点串成一条线，都是识记加理解的考点。

## 1. 概念与要点

**软件生命周期**。软件从构思到退役的全过程，常见阶段：问题定义、可行性研究、需求分析、概要设计、详细设计、编码、测试、运行维护。**需求分析**回答"做什么"，设计与编码回答"怎么做"；**维护**历时最长，分为改正性维护（修错）、适应性维护（跟环境）、完善性维护（加功能）、预防性维护（改结构）。

**中间件**。位于操作系统与应用软件之间的系统软件，**屏蔽底层异构**，提供通信、事务、消息等公共服务。按功能常见分类：数据库中间件、消息中间件、交易中间件、对象中间件。

**操作系统五大管理**：**进程管理**（也叫处理机管理）、**存储管理**（内存）、**文件管理**、**设备管理**、**作业管理**。

**进程三态**：就绪（万事俱备只差处理机）、运行（正在占用处理机）、阻塞（等待某事件，如 I/O）。常见转换：时间片用完运行转就绪；等待事件运行转阻塞；事件完成阻塞转就绪。

**死锁四个必要条件**（同时成立才可能死锁）：

| 条件 | 含义 | 破坏思路 |
|---|---|---|
| 互斥 | 资源一次只能一个进程用 | 改为共享（常做不到） |
| 不可剥夺 | 已占资源不能被抢 | 允许抢占 |
| 请求与保持 | 持有资源又申请新资源 | 一次性申请全部资源 |
| 循环等待 | 进程头尾相接互相等待 | 资源有序分配 |

**嵌入式系统特点**：面向特定应用、软硬件紧密耦合、可裁剪、实时性强、可靠性高、资源受限。

## 2. 关键考点

> 💡 **关键考点**：
> 1. 需求分析管"做什么"，设计管"怎么做"；维护里改正性修错、适应性跟环境、完善性加功能、预防性改结构。
> 2. 死锁四条件：互斥、不可剥夺、请求与保持、循环等待；一次性分配破坏"请求与保持"。
> 3. 进程三态转换：等 I/O 进阻塞，时间片完回就绪；嵌入式 = 特定应用 + 软硬一体 + 实时 + 资源受限。

## 3. 常见考法

- 问"确定系统做什么"或"投入时间最长"属于哪个阶段。
- 给一段维护描述，判断是改正性、适应性、完善性还是预防性。
- 给进程状态转换场景（等磁盘、时间片到、被高优先级抢占）判断转入哪一态。
- 问死锁四条件名称，或"一次性申请全部资源"破坏了哪一个。
- 问中间件的核心作用，或嵌入式系统的特点。

常见坑：把需求分析当成"怎么做"；把时间片用完当成阻塞；把"请求与保持"说成循环等待；认为嵌入式资源无限、不需实时。

## 4. 速记

口诀：**"需求做什么，维护最长活；死锁互不请环，嵌入特硬实时裁。"**

| 进程转换 | 原因 | 去向 |
|---|---|---|
| 运行 → 就绪 | 时间片用完或被抢占 | 就绪队列 |
| 运行 → 阻塞 | 等待 I/O 或事件 | 阻塞队列 |
| 阻塞 → 就绪 | 事件完成 | 就绪队列 |
| 就绪 → 运行 | 被调度程序选中 | 占用处理机 |
